# SF-VIDEO-1 — มาตรฐานสร้างและเรนเดอร์วิดีโอของปิ๊กบน Mac

ใช้กับทุก AI ที่เริ่มงานวิดีโอในบัญชี Mac นี้ รวมการทำ preview, export, สร้างเฟรม, ประกอบเสียง หรือถอดทั้งคลิปเพื่อ QA **ให้พีก RAM ต่ำก่อนความเร็ว โดยไม่ลดคุณภาพ** จุดเข้าเครื่องเดียวกันคือ `"$HOME/.local/bin/safarium-render"` ใช้ได้จากคนละโฟลเดอร์และคนละ AI

## ก่อนเริ่มตัววาดหรือเปิดไฟล์สื่อขนาดใหญ่

1. เข้าคิว **ก่อน** เปิด WebKit, decoder, GPU scene หรือ encoder. ให้คิวเริ่มคำสั่ง foreground ของงาน อย่าสตาร์ตโปรเซสหนักไว้ก่อนแล้วเข้าคิวตอนเขียนไฟล์เท่านั้น ระหว่างรอไม่ต้องโหลดภาพหรือเสียง สั่ง `safarium-render status` เพื่อดูสถานะ
2. หนึ่งงานที่ได้สิทธิ์ใช้ **หนึ่ง render worker** ภายในด้วย คิวไม่ได้เปลี่ยนจำนวน worker ของโปรแกรมภายนอกให้เอง คำสั่ง foreground ต้องรอลูกทุกตัว และให้โปรเซสทำสื่ออยู่ใน session ของงานจนจบ ไม่ส่งงานให้ daemon/แอปอื่นหรือแยกตัวไปทำหลังคำสั่งคืนค่า ห่อเฉพาะชั้นนอกสุด ไม่ซ้อนคิว
3. งาน HTML ที่ตรงสัญญาของตัวกลางใช้ `safarium-render html …` (รองรับ single-pass AVAssetWriter, `--codec h264|hevc|hevc-alpha|prores4444`, `--transparent`, `--pixel-format bgra|nv12-vimage`, `--snapshot-quality fast|sharp`, `--subtitles FILE.srt [--subtitle-lang ISO639-2]`). งานสื่อประกอบเพิ่มเติมใช้ `safarium-render extract-audio|mix-audio|gif|cutout|hybrid …` (ทั้งหมดบน Apple frameworks ไร้ FFmpeg). งานที่ต้องใช้ตัวสร้างเฉพาะ (เช่น Swift/Metal วาดทีละเฟรม) ใช้ `safarium-render run -- /absolute/path/to/foreground-renderer ...` เมื่อยืนยันแล้วว่าไม่มี Chromium/Chrome, FFmpeg/ffprobe/libav หรือ fallback ที่แอบเรียกมัน รวมของที่ฝัง/แถมมากับแพ็กเกจ ไม่เปลี่ยนชื่อ executable เพื่อเลี่ยงข้อกำหนด หากคิวหรือ backend ที่รักษาสเปกได้ไม่พร้อม ให้รายงาน ไม่ข้ามคิวหรือสลับเอนจินเงียบ ๆ
4. กำหนดสเปกก่อนรันจากต้นฉบับหรือความต้องการของปิ๊ก: ขนาดภาพ, fps และเวลาแต่ละเฟรม, ระยะ, codec/profile/bitrate, สี/ช่วงสี, alpha/HDR, ฟอนต์, แทร็กเสียง/ซับ/ภาษา, sample rate/channels และเวลาเริ่ม–จบ ฟีเจอร์ที่ตัวกลางไม่รองรับให้ใช้ทางที่ตรวจแล้วผ่านคิว หรือแจ้งข้อจำกัด ห้ามแปลงงานโปร่งใสเป็น H.264 ทึบ ห้ามตัดเสียงหรือซับเพื่อให้ผ่าน

## กฎสำหรับตัวเขียนโค้ดสร้างวิดีโอ

- **ภาพ:** วาด/อ่าน → ส่งให้ปลายทางตามลำดับ → ปล่อยเฟรม เมื่อตัวเขียนยังไม่พร้อมให้ผู้ผลิตรอ (backpressure) คิวเฟรมและคิวเรียงลำดับมีขนาดจำกัดเสมอ ไม่เก็บลิสต์ JPEG/PNG/base64 หรือภาพดิบทั้งตอน การเปลี่ยนวิธีส่งต้องรักษาทุกไบต์/เฟรม/เวลา ส่วนการแบ่งฉากหรือล้างแคชของเอนจินอื่นต้องทดลอง A/B กับงานนั้นก่อน ไม่ตั้งเป็นค่าเริ่มต้นเพียงเพราะคาดว่าจะประหยัด
- **เสียง:** เมื่องานคืออ่าน/คัดลอก/แฮช/ส่ง PCM เดิม ให้แบ่งที่ขอบ sample frame และส่งบล็อกขนาดจำกัด (ทดลอง 16,384 เฟรม), ปล่อยบล็อกก่อนอ่านต่อ ตรวจจำนวนตัวอย่าง เวลา ช่องเสียง sample rate/bit depth และก้อนท้าย ไม่อ่าน WAV ยาวทั้งก้อนเพื่อส่งต่อ หากต้องมิกซ์ กรอง ทำรีเวิร์บ ตรวจความดัง หรือมี lookahead ให้รักษาสถานะ/หาง/บริบทรอยต่อของ DSP และตรวจผลเทียบทั้งแทร็ก; ห้ามรีเซ็ตฟิลเตอร์ทุกบล็อกหรือสลับเป็นตัวประมาณเพื่อประหยัด RAM
- **แก้เฉพาะเสียง:** เมื่อ track ภาพเดิมใช้ต่อได้ ให้คัดลอกตัวอย่างภาพที่บีบอัดและเวลาเดิม ไม่เปิดหน้าเว็บมาเรนเดอร์ภาพซ้ำ นี่เป็นวิธีรักษาภาพที่ตรวจแพ็กเก็ตแล้ว ไม่ใช่ตัวเลขผลลด RAM เพิ่มอีกก้อน การตัดที่ไม่ใช่คีย์เฟรม การเปลี่ยนสี/ซับฝัง หรือกรณีต้องแก้พิกเซล ต้องตรวจตามสัญญาของงาน ไม่บังคับให้ copy ทั้งที่ผลไม่ถูก
- **ห้ามใช้การลดคุณภาพแทนการลด RAM:** ไม่ลด resolution/DPR, fps, bitrate, sample rate, precision, สี, alpha, passes หรือจำนวนเฟรม/ช่องเสียง ไม่สลับภาพเบลอหรือภาพแทน และไม่ลดเกณฑ์ภาพให้เงียบ ๆ การลดพื้นที่แคช/แบ่งงานใช้ได้เมื่อผลที่ส่งออกยังเหมือนเดิม

## ตรวจรับจากไฟล์ส่งออก

- สำหรับการลด RAM อย่างเดียว เทียบภาพที่ถอดจากไฟล์ตามลำดับ/เวลาจริงและตรวจเสียงที่ตำแหน่ง sample จริง ถ้าเป็นงานคัดลอกแทร็กให้เทียบข้อมูลแพ็กเก็ตและ PTS/duration ด้วย ตรวจฟอนต์/สี/ภาพโปร่งใส/ซับและภาษา/metadata เมื่อเป็นส่วนหนึ่งของงาน
- ในตัวตรวจที่ถอดเป็น NV12 ให้อ่านไฟล์อ้างอิงจนจบและปิด reader ก่อนเปิดไฟล์ใหม่ แฮชเฉพาะไบต์ภาพที่ใช้งานของทุกแถวและทั้งสองระนาบ บันทึกขนาด รูปแบบ สี และเวลาควบคู่กัน ไม่สร้างสำเนาเต็มเฟรมเพื่อแฮช และไม่เอาไบต์เติมท้ายแถวมาตัดสินภาพ ภาพอ้างอิงแบบ BGRA ทึบ 1:1 ที่ต้องเทียบแบบ exact สามารถตรวจทีละแถบแทนการสร้างภาพเต็มสองชุดได้ เมื่อพิสูจน์กับรูปแบบนั้นแล้วว่าครบทุกแถวและคืนพิกัดเดิมเมื่อภาพต่าง แม้ผิดแค่บิตสุดท้าย
- `RetainedViewport` ใช้ **64 แถว** ต่อแถบสำหรับคู่ภาพ sRGB BGRA 8 บิตที่ตรงรูปแบบที่ทดสอบจริง รวมแถบท้ายที่สั้นกว่า 64 แถว หากสี/รูปแบบไม่ตรงหรืออ่านแถบไม่ได้ให้ใช้การเทียบเต็มภาพเดิม ผลการตรวจยังต้องตรงทุกพิกเซล ห้ามเปลี่ยนเป็นสุ่มแถว/เว้นเฟรมหรือเปิด `--trust-rect` เพื่อลด RAM
- `safarium-render verify FILE.(mp4|mov)` อ่านไฟล์ที่รองรับ; `safarium-render verify REFERENCE.(mp4|mov) CANDIDATE.(mp4|mov)` เปรียบเทียบภาพที่ถอดได้ เสียง (AAC) ซับ (`tx3g`) และเวลาแบบ exact โดยใช้ระบบ Apple อ่านทีละไฟล์. **inspect ไฟล์เดียวไม่ใช่การยืนยันว่าเหมือนต้นฉบับ**. ตัวตรวจนี้รับ SDR BT.709 H.264, HEVC, ProRes 422/4444 (ทึบ NV12 และโปร่งใส BGRA alpha), AAC โมโน/สเตอริโอไม่เกินหนึ่งแทร็ก และซับไตเติล `tx3g` ไม่เกินหนึ่งแทร็ก; ไม่รับรอง HDR/metadata พิเศษหรือ codec อื่นนอกเหนือจากนี้ ต้องใช้ตัวตรวจรูปแบบนั้นเพิ่มเติม ห้ามข้ามเงื่อนไข
- การย้ายเอนจินเป็นอีกการทดลองหนึ่ง: ระบุชัดหากไม่ตรงแบบ exact; ห้ามเรียกว่า “คุณภาพเหมือนเดิม” จากการที่ไฟล์เปิดได้หรือคำสั่ง exit 0. เกณฑ์เดิม Safarium สำหรับการเทียบข้ามเอนจินยังเป็น SSIM ≥ 0.97, PSNR ≥ 30 dB, ΔE00 p95 ≤ 2 และตรวจข้อกำหนดเสียง/เวลาแยก
- ทดสอบกับ scratch และเผยแพร่ไฟล์เมื่อเขียน/ตรวจเสร็จ ไม่ทับต้นฉบับของปิ๊ก การวัด RAM ให้ระบุว่ารวมโปรเซสใดบ้างและใช้พีก ณ เวลาเดียวกัน ไม่บวกพีกคนละเวลา และไม่เหมารวมว่า WebKit ประหยัดกว่า Chromium เป็นเปอร์เซ็นต์เมื่อข้อมูลเก่าไม่ได้วัดแบบเดียวกัน

## คำสั่งสำหรับ AI

```sh
"$HOME/.local/bin/safarium-render" status
"$HOME/.local/bin/safarium-render" html "$SCENE/index.html" --output "$SCRATCH/clip.mp4" \
  --width 1080 --height 1920 --fps 30 --frames 60 --start 24 --bitrate 20000000 \
  --audio "$SCENE/assets/voice.wav" --audio-start 24
"$HOME/.local/bin/safarium-render" verify "$REFERENCE" "$SCRATCH/clip.mp4"
```

ตัวเลขในตัวอย่างเป็นของ EP30 ไม่ใช่ค่าบังคับสำหรับทุกโปรเจกต์ งานเงียบต้องตั้งใจเลือก `--video-only`; ถ้าเป้าหมายเป็นภาพนิ่ง SVG ที่เขียนออกจากโค้ดโดยตรง ไม่จำเป็นต้องเปิด renderer เพื่อสร้างไฟล์ต้นทาง
