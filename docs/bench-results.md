# SafariumRaster vs OpenCV 5.1 - acceptance benchmark

Generated by `sdk/python/tests/bench_raster.py` (selection: all; N = 15 timed samples per engine; load1 at start 7.3). Rows marked `†` are **provisional** (load1 > 4 during the run): 108 of 108. Reference: opencv-python-headless 5.1.0.95; shim dylib: `libSafariumRaster.dylib`. Machine: Mac17,3, 10 CPUs.

## Verdict rules (thresholds)

- **Speed**: median wall time over N samples after warmup, Python-call overhead included. Each engine runs in several fresh processes interleaved A/B/B/A (order flips every round and per case); the CI is a block bootstrap over processes, so one process caught in a load spike cannot fake a win. All 1-thread work of the whole run is done before any default-thread run. WIN = Safarium <= 0.95x cv2 median and 95% order-statistic CIs do not overlap; LOSS = >= 1.05x with CIs apart; else TIE. Two configs: `1T` = both libraries at `setNumThreads(1)` (SF-VIDEO-1 default, the CPU headline) and `dflt` = each library at its own default thread count (GPU/ANE/Metal count only here, per Pick's Q3 ruling).
- **RAM**: fresh child per (case, engine); baseline taken after imports and input allocation; peak = max(ru_maxrss growth, 1 ms-sampled RSS peak - baseline), and the same for `phys_footprint` (sees GPU/unified memory); the worse of the two verdicts counts. WIN <= 0.9x cv2, LOSS >= 1.1x, differences under 1 MiB are noise = TIE. Streaming cases also require RSS slope < 1 MiB per 100 frames.
- **Quality**: parity gate = raster_parity bar (SSIM >= 0.97, PSNR >= 30 dB, dE00 p95 <= 2; numeric outputs rel. error <= 1e-06); failing it is a LOSS. Where a float64/analytic ground truth exists the accuracy gate compares RMSE vs truth: WIN <= 0.9x cv2's error, LOSS > cv2's error * (1 + 0.001). No truth = parity-only (TIE when it passes). Default output matches OpenCV; more accurate results would sit behind an opt-in flag.
- **File size** (encoders): bytes at equal SSIM (quality knob bisected per engine, decoded with Pillow) or lossless bytes with exact round-trip. WIN <= 0.95x, LOSS >= 1.05x.
- **Overall** (`dflt` speed headline): BETTER = no LOSS on any metric and at least one WIN; a LOSS is never averaged away. `Overall 1T` uses the 1-thread speed instead. UNSUPPORTED = the shim does not implement it yet.
